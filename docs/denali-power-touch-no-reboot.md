## Touch module / ADSP client

Teardown audit against the built source: `msm_drm_uninit()` attempts `adreno_system_suspend()` before reverse `component_unbind_all()`. On the active-submit timeout, suspend resumes the scheduler and returns `-EBUSY` before disabling GPU runtime PM. The GMU component then tears down MMIO, power domains and IRQs, and `adreno_unbind()` can enter suspend a second time because runtime PM remains enabled. Removing just the second suspend call would still leave the first-failure path without a quiescence guarantee. A runtime candidate must keep GMU resources valid until GPU work is fenced, not merely move or suppress the warning. Separately, the devfreq boost QoS request is removed with its notifier still registered; the core's QoS callback calls `update_devfreq()`, and the notifier is unregistered in the devfreq object's release callback. Check outstanding references and callback drainage before relying on unregister order alone. Neither issue was exercised on the running machine from this build-only snapshot. The follow-up build-only patch `denali-adreno-gmu-release-irqs-before-mmio.patch` places both `free_irq()` calls after the final GMU suspend attempt but before domain detach, `iounmap()` and buffer release. Both handlers access GMU registers, and either can queue `recover_work`; `free_irq()` drains the handlers, not that queued work. The revised candidate evaluated on native AArch64, and applying the three GMU patches to the pinned Next24 GMU source confirmed this call order. The separate `denali-adreno-gmu-unwind-partial-irq-bind.patch` covers failed acquisition: a missing or deferred platform IRQ never reaches `request_irq()`, and bind rollback frees zero IRQs on HFI failure, only HFI on GMU IRQ failure, and both on later failure, before MMIO unmap. Source checks against the full four-patch GMU stack and native evaluation of the payload derivation passed. On the Surface, `nix build --max-jobs 1 --cores 2 --no-link .#checks.aarch64-linux.denali-adreno-gmu-compile-object` now applies the full stack via the kernel derivation's normal GNU patch phase and compiles `a6xx_gmu.o` against the locked configuration. Read-only inventory of the running Denali in boot `34b2b4af-6b0c-4ab5-917f-898ad80b0599` identified GPU `qcom,adreno-43050c01` (X185/C512v2, A7xx Gen2), GMU `qcom,adreno-gmu-x185.1`, and `cx`/`gx` domains on GPUCC. The live GPU and GMU are separate, single-device SMMU groups, default type `identity` (`/sys/kernel/iommu_groups/{11,12}/type` on this boot). This is the *default* type, not a statement that the live bound driver's private page tables are bypassed. Next24 `iommu_detach_device()` calls `__iommu_group_set_core_domain()`: absent a DMA owner, it reinstates that default, not a blocked domain. Detaching the current paging context therefore is **not** a substitute for fencing DMA, and GPU-only isolation would omit the GMU stream. Do not change the default domain or detach either device on the daily system.

Likewise, `genpd_runtime_suspend()` does not propagate the result of `genpd_power_off()`. `dev_pm_genpd_synced_poweroff()` sets a provider hint, not an acknowledgement. X1E GPUCC's GX GDSC has an OFF poll in the provider implementation, but passing a runtime-PM call or treating a generic `gx_is_on() == false` as confirmation is inadequate: the A7xx helper also returns false when the GMU is uninitialized or when just its GX clock is off. Do not infer completed power collapse from either proxy.

Before release, the design needs a proof that remains valid across halt release, reset/power-down, and both DMA streams. The practical split is (1) confirm a platform-defined terminal stop while the GMU resources and suppliers are live; (2) give ownership of DMA memory, mappings and PM references to a lifetime that is not destroyed by the component's unconditional devres release if that proof fails. Reordering the void callbacks, returning early from one, relying on a PM success code, and plain IOMMU detach do not implement that contract. No lifetime redesign or new shutdown/reset sequence has been validated. Until then, keep the binding stack build-only; neither this source audit nor the mock ACK tests identify the cause of the `deep` immediate return.

### Observe WSA hardware votes without changing FullIO

The live WSA node `6b00000.codec` names `mclk`, `macro`, `dcodec`, and `fsgen`. Its Q6PRM clock specifiers for `macro`/`dcodec` are DT IDs 102/103, mapped by Next24 `q6prm-clocks.c` to DSP hardware block IDs 1/2 and CCF clocks `LPASS_HW_MACRO`/`LPASS_HW_DCODEC`. These are prepare/unprepare hardware votes, not `q6prm_set_lpass_clock()` MCLK changes. Following only the latter would miss the reported standby issue. Both vote/unvote symbols are present in the running kernel.

For a future attended `s2idle` trace, add `--wsa-votes` to `sudo bash scripts/denali-suspend-trace.sh s2idle NEW_OUTPUT_DIRECTORY`. It records the individual CCF prepare/enable counts before and after (missing entries report `unavailable`), Q6PRM vote/unvote entry and return, and buffer/probe statistics. Do not use the global `clk_summary` as a baseline here: its Next24 implementation calls `clk_pm_runtime_get_all()`. The narrow per-clock counters are plain debugfs `u32` reads. Pair command entries with returns by task and check for lost events; a retained prepare count and no unvote in a complete trace indicate a retained **Linux** vote, not a direct readback of firmware clock state. Q6PRM hardware IDs can also be used by other LPASS consumers; use trace ordering and the CCF counts rather than assuming a shared vote belongs exclusively to WSA. The attended actual capture (`/tmp/denali-wsa-votes-1175936.summary`, 02:26:38–02:30:05 local) kept AC, eDP only and the normal silent FullIO keeper, with no Chrome stream. This does not read firmware clock state or exclude other LPASS votes. ### Distinguish the PSCI system idle request from RPMh activity

The current boot reports PSCI 1.1 with OSI and three clusters. The live `/psci/power-domain-system/domain-idle-states` resolves to `domain-sleep-0`, parameter `0x0200c354` with a 9 ms minimum residency; this is different from CPU retention `0x00000004` and both cluster states. Next24 `__psci_enter_domain_idle_state()` traces `power:psci_domain_idle_enter` **after** choosing a hierarchy state and **before** calling `psci_cpu_suspend_enter()`. `psci_domain_idle_exit` runs whether that call succeeded or failed. The raw cpuidle `s2idle/usage` counts attempts, not that choice or successful residency; local-clock `s2idle/time` is not the OS-suspend clock delta. Similarly, periodic RPMh callbacks in the prior trace are not a record of the actual value passed to PSCI.

The opt-in `--psci-system` collector reads and validates the live DT phandle and parameter, and records only matched `s2idle` PSCI entry/exit events plus the existing sleep/wake and firmware snapshots. It is separate from `--wsa-votes` and leaves high-frequency RPMh probes off; save and inspect buffer statistics before interpreting missing events. A matching entry proves Linux issued the system-state request, not that firmware accepted it. A no-hit trace is useful only if filters armed, events were not lost, and a genuine `s2idle` cycle completed. Device-tree lookup, source event fields and shell syntax checked; live arming and capture not yet performed. No sleep policy or kernel change.

## What requires a local operator later

1. Compare the next ordinary lock's label with SAM `BAT1`. Test actual energy change over a longer stable battery interval separately; do not infer charge policy from a short unplug/replug.
2. Before any sleep attempt, have the owner at the power button with the current boot/recovery entry intact. Separate short explicit `deep` and `s2idle` tests and check the actual mode and wake logs. A failed resume can require power cycling, so do not run these while reboot is unavailable. Once short cycles are reliable, measure ≥2 h at midrange charge with matched peripherals/network, using `BAT1/energy_now` plus root-readable Qualcomm sleep residency. Read the counters; do not change the PM debug policy to obtain them.
3. Validate FullIO playback and simultaneous internal MicArray after waking before doing any WSA or ADSP A/B; service state alone does not prove this. Retain protection, 0 dB, HHKB, touchpad, OLED, NVMe, Wi-Fi and Bluetooth checks. Do not set auto-suspend before wake reliability, drain and rollback are all accepted.
